# Tessera

- По указанию пользователя работать непосредственно в `main`, без PR. Сохранять этапы отдельными проверяемыми коммитами; публикацию релиза и необратимые действия выполнять только в согласованном объёме.
- Главный источник требований — `target-specification-v4.0.md`. Перед началом каждого этапа обязательно прочитать [`audit.md`](audit.md): подтверждённые замечания, согласованные решения, приоритеты и критерии тестирования. Проверять актуальность замечаний на текущем `main`, устранять относящиеся к этапу риски и честно отмечать незакрытые. Если аудит и спецификация расходятся, не подменять требования молча — зафиксировать противоречие и предложить минимальное согласование. Прототип — только пример идей; совместимость с его кодом и данными не требуется. Базы выпущенных версий Tessera сохранять миграциями. Не менять функциональные требования ради скорости.
- Работать небольшими проверяемыми этапами. Пользователь разрешил последовательную реализацию всей v4.0 небольшими проверяемыми этапами без повторного согласования каждого этапа. Этапы 1–4 реализованы; этап 5: независимые быстрые формы с наследованием правил/defaults обычной формы, явным сохранением и сохранностью баз 0.4.0 через миграцию 5. Далее — страховочные черновики и остальные требования v4.0. Статус готовности каждого коммита подтверждать CI, не объявлять незавершённый прогон успешным. Share файлов, вложения, Decimal/формулы, режимы/сводки, история и почта проверяются отдельными этапами. Ручная приёмка дополняет автотесты там, где нужны физические устройства/реальные личные учётные данные/подписи.
- React/TypeScript/Vite, Zustand только для UI, TanStack Virtual и ограниченные SQL-выборки. Строки UI — через i18next, русский по умолчанию.
- Бизнес-правила, DDL, миграции, HLC, история и журнал — в общем TypeScript-ядре. Rust/Kotlin — только адаптеры ОС/SQLite. UI обращается к repository API, не к SQL.
- Нативная SQLite — единственный источник истины. Запрещены production localStorage, sql.js, browser fallback и скрытые заглушки. Android сначала использует бесплатный community SQLite.
- Все обращения к соединению проходят через последовательную очередь адаптера. Правка объекта, версия и change_log атомарны; HLC сохраняется в той же транзакции. Desktop — один процесс-писатель.
- UUID полей стабильны; записи в одной таблице records с валидным JSON-объектом. Неизвестные значения сохранять. Новая схема — новая транзакционная миграция; перед изменением существующей схемы согласованный backup. Не сбрасывать неподдерживаемую БД.
- Только явное сохранение создаёт запись/версию. Отмена ничего не пишет. Будущие черновики — локальные файлы, без секретов и синхронизации. Быстрые действия без пользовательской версии.
- Никакого произвольного JS/SQL пользователя, фонового сервиса, обязательного аккаунта или сети. Секреты не логировать и не индексировать.
- Существенные изменения проверять реальными тестами; тесты/бенчмарки только dev/CI. Не выдавать Node SQLite за проверенный Capacitor/Tauri bridge. Не реализованный sync-протокол не считать протестированным.
- Перед завершением: `npm run typecheck`, `npm run lint`, `npm run test:all`, `npm run build`; при доступном Rust — `npm run test:native`. Проверить CI и честно указать блокировки. Windows/Android-проверки требуют соответствующей среды.
- Не добавлять необязательные зависимости и архитектурные документы. Технический контракт — код, миграции, тесты; команды и ограничения — README.
