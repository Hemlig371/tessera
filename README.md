# Tessera

Личная local-first база для Android и desktop. Источник требований — [target-specification-v4.0.md](target-specification-v4.0.md). Версия **0.14.0, этап 14 — отдельные экраны карточки и редакторов**; остальная спецификация реализуется последовательно.

**Старт библиотеки (API):** конфигурация библиотеки сохраняет каталог коллекций (список/карточки), конкретную коллекцию с необязательным профилем либо последний открытый раздел. Последний раздел локален для устройства и не создаёт HLC/версий/событий журнала. Удалённая или чужая цель безопасно возвращает каталог без перезаписи сохранённого выбора. Сводки ещё не реализованы и пока не предлагаются как старт.

**Совместимость dev-баз:** текущий bootstrap заменяет цепочку dev-схем 1–7. Существующая dev-база отклоняется без удаления/перезаписи. Перед переходом сохраните исходные данные и экспортируйте доступные коллекции в совместимой сборке. Полный «Экспорт БД» ещё не реализован; CSV не сохраняет историю, структуру и связи как переносимый архив. Для ценных dev-данных сохраняйте исходный каталог для работы совместимой сборкой. После первого публичного релиза применяются последовательные миграции с проверкой сохранности.

**История (ядро):** явные сохранения удерживают детерминированные последние 20 версий по `(HLC, ID)`, без ограничения календарного возраста. Отсечение и ручная очистка имеют монотонные технические маркеры: старый повтор не восстанавливает удалённую историю. Доступны API чтения/очистки и примитив объединения истории, проверяемый между независимыми SQLite. UI истории, восстановление версии и полный протокол синхронизации ещё впереди.

**Транспортный журнал (ядро):** до подключения и после `detached` пользовательские сохранения/CSV не накапливают `change_log`. Первое локальное подключение атомарно строит исходные события из актуальных таблиц, удерживаемой истории и маркеров; повторное подключение не дублирует их. `paused` продолжает сохранять дельты. Компактация удаляет только префикс, подтверждённый всеми зарегистрированными устройствами; без устройств активный журнал сохраняется. Устаревший курсор и чужой `dataset_id` отклоняются. `detached` меняет `dataset_id` и очищает только состояние прежнего журнала. Эти API — фундамент локального протокола; почта, доставка пакетов и пользовательская настройка синхронизации ещё не реализованы.

**CSV и A-04:** чтение/декодирование/разбор, проверка и импорт показывают прогресс. Отмена до финального commit откатывает весь импорт вместе с версиями, HLC, журналом и индексами; тот же проверенный файл можно импортировать повторно. Повреждённая кодировка отклоняется без замены символов. Ограничение исходного файла — 100 МиБ; разобранный документ остаётся в памяти. Во время атомарной записи остальные операции базы ожидают очередь. Нативный contract проверяет также принудительное завершение SQLite-процесса и восстановление предыдущей базы. Автовозобновление импорта после перезапуска пока не реализовано (F-05).

**Android CSV-экспорт:** сначала формирует приватный временный файл, затем копирует готовые байты в выбранный DocumentsProvider. Успех — только после закрытия потока. Обычная ошибка/отмена очищает документ по возможности; оставшиеся приватные staging-файлы удаляются при загрузке плагина. При убийстве процесса во время финального копирования провайдер может оставить неполный внешний документ; атомарность любого Android-провайдера не обещается. CSV остаётся экспортом коллекции, а не резервной копией БД.

**Оформление устройства:** системная/светлая/тёмная темы, обычная/компактная плотность и размер текста 100–150% доступны через «Оформление» на Android и desktop. Настройки сохраняются в локальной SQLite без HLC, пользовательских версий или журнала. Системная тема меняется вместе с ОС; reduced motion учитывается. Виртуальные строки измеряются по фактическому содержимому и увеличению шрифта. Это отдельный шаг UX: главные экраны и полная навигация ещё впереди.

**Режим конструктора:** «Конструктор» открывает настройки библиотеки/коллекции, полей, компоновок, быстрых форм, профилей и пресетов с предпросмотром записей. В обычном режиме этих настроек нет; профиль выбирается обычным селектором, варианты создания — через меню `+`. Создание новой библиотеки/коллекции входит в конструктор. «Готово, к данным» и Android Back возвращают к данным; открытый редактор сначала закрывается по прежним правилам. Режим не пишет данные/историю, не меняет черновики и не включается сам после перезапуска. Работающие редакторы сохранены и перенесены на отдельные экраны.

**Адаптивная компоновка:** редактор строк формы, карточки и быстрой формы задаёт 1–3 колонки, группы, порядок полей/строк и свёрнутые по умолчанию поля. На телефоне строки перестраиваются в одну колонку. Ошибка обязательного поля раскрывает его для ввода; сворачивание не стирает значение. Старые `full`/`half` настройки читаются без перезаписи базы; новая структура сохраняется только по явному сохранению настройки. Неназначенное поле остаётся в конце, удаление строки не удаляет поле или данные. Карточка и быстрая форма сохраняют независимую компоновку; у быстрой формы общие с обычной формой только правила проверки и defaults. Строки пока относятся к формам/карточкам, не новым режимам списка.

**Отдельные экраны:** карточка заменяет список в рабочей области, создание/редактирование/перенос и настройки открываются как страницы с заголовком и «Назад», без модального слоя. Явное сохранение, «Закрыть» создания и «Отмена» редактирования сохраняют прежние правила. Возврат восстанавливает профиль, поиск, цепочку связей, фокус и положение списка; отмена правки возвращает также позицию чтения карточки. После Save того же запроса обновляется уже загруженный диапазон ограниченными SQL-страницами; список сохраняет DOM/прокрутку до завершения обновления. Фильтры и профиль продолжают определять состав и порядок записей. Android Back и Escape закрывают текущий редактор/шаг цепочки. Главные экраны библиотек и навигационные старты — следующий этап.

**Согласованный целевой UX (ещё не реализован целиком):** [ui-specification.md](ui-specification.md) — темы, навигация Android/desktop, визуальный конструктор, экран записи, черновики только создания, новая система именованных профилей отображения одной коллекции и пресеты создания. Это **не** возврат прежней исключённой концепции «Представления». Дополнения к бизнес-правилам внесены в основную v4.0; [audit.md](audit.md) обязателен для каждого дальнейшего этапа, включая актуализированный F-06. Для dev/CI описаны [универсальные приёмочные библиотеки](tests/fixtures/README.md): питание, заметки, база знаний, проекты/задачи. Начаты dev/CI-фикстуры «Заметки», «Проекты и задачи» и «База знаний»: доступные типы, связи, черновики, профили и пресеты через Repository API. Остальные части библиотек пока планируются; в пользовательской базе фикстур нет.

**Черновики создания:** один приватный локальный файл на коллекцию, debounce 3 с, запись при закрытии/неактивности. Повторное создание (в том числе кнопкой быстрой формы) открывает обычную форму с введёнными значениями; вход в коллекцию её не открывает. Только успешное сохранение удаляет файл. Редактирование и перенос существующих записей его не читают и не меняют. Ошибка записи файла оставляет форму открытой; мгновенная гибель процесса до debounce может потерять последние символы. Секретные/неопознанные типы исключены; неизвестные значения ранее известных полей сохраняются. Базы 0.5.0 и миграции 1–5 не изменены. Перестройка FTS/текстовых ключей ограничивает только запросы соответствующей коллекции/библиотеки, которым нужны эти ключи; числовая сортировка/фильтрация остаётся доступной. Готовность связей проверяется по исходной коллекции нужного поля, без блокировки независимых коллекций (A-02). Следующий этап — A-04: отмена больших CSV-импортов без частичного сохранения, затем Android Share и остальные требования v4.0. Инструкция для Codex — [AGENTS.md](AGENTS.md).

**Защита формы A-01:** обычное редактирование передаёт исходный HLC. Если запись изменилась, сохранение отклоняется без записи версии/журнала; можно загрузить актуальную запись либо явно сохранить свою редакцию. Повторное подтверждение тоже проверяет HLC. Это локальная защита ввода, не реализация синхронизации.

Рабочий путь: библиотека → коллекция → поля → явное сохранение записи в нативную SQLite. Доступны переименование, значок/цвет, порядок, удаление с отменой; восемь типов: текст, многострочный текст, Markdown, логическое значение, целое число, календарная дата, прямая и обратная связь. Ноль и `false` — полноценные значения. UUID поля не меняется при переименовании; удаление сохраняет его значения в записях. Тип существующего поля не преобразуется автоматически.

Форма, карточка и список настраиваются независимо: порядок, группы, видимость, ширина; у формы — обязательность, подсказки и defaults. У списка — строки/карточки/таблица, SQL-фильтры, сортировка и группировка. Конструктор доступен на мобильной ширине. Поиск по словам/префиксам работает в коллекции, библиотеке и глобально, с Unicode-нормализацией. Большие списки читаются SQL-страницами по 100–200 записей и виртуализируются.

**Представления (именованные профили отображения):** переключатель в заголовке коллекции выбирает независимые настройки одного набора записей. «Представления» позволяют создать копию текущей конфигурации, переименовать, изменить порядок, назначить профиль по умолчанию и удалить лишний (последний удалить нельзя). Кнопка «Список» редактирует выбранный профиль: поля/компоновку, режим строки/карточки/таблица, сортировку, группировку и фильтры. Смена профиля не меняет записи или их версии. Индексы учитывают требования всех активных профилей. Kanban, календарь, дерево, Гант, граф, относительные фильтры и итоги пока не реализованы.

Миграция 6 переносит существующий список в профиль по умолчанию с прежним UUID/HLC и точной конфигурацией; без сохранённого списка создаётся «Список». Исходные `ui_configs` сохранены, активные списки читаются из профилей. Обновление заполненной схемы 0.5.0 и откат/повтор после сбоя проверены через Node SQLite и Rust/rusqlite: прежние records/UUID/связи/история/журнал/form/card/quick_forms не изменяются. Конфигурации профилей имеют собственные UUID/HLC и журнал, но настоящая синхронизация ещё не реализована. Android/WebView и Linux process-restart сценарии добавлены в CI; их результат нужно проверять по конкретному коммиту.

**Пресеты создания:** «Пресеты создания» в коллекции настраивают именованные предзаполнения по UUID полей, обычную/быструю форму и действие короткого нажатия `+`. Можно задать буквальное значение или текущую локальную дату для поля даты (вычисляется при открытии, без записи в БД). Дополнительные варианты доступны через стрелку, удержание, ПКМ и клавиатуру. Быстрая форма и пресет независимы: пресет может заполнять скрытые поля, сохраняя обычные правила Save. Черновик проверяется первым; при его наличии пресет не применяется, открывается обычная форма с восстановленным вводом. Редактирование существующих записей пресеты не использует. Удаление назначенного пресета возвращает обычное создание. Несовместимость после удаления поля сохраняет конфигурацию пресета и выдаёт ошибку, не создавая запись.

Миграция 7 добавляет только `creation_presets`; настройки действия `+` входят в конфигурацию коллекции. Пресеты — самостоятельные UUID/HLC конфигурации с журналом, но не `records` и не пользовательские версии. Выбор/разрешение пресета ничего не пишет. Проверено обновление исходной заполненной базы 0.5.0 через миграции 6–7. Частичная dev/CI-библиотека «Проекты и задачи» создаёт структуру/пресет через Repository API; поддержаны самоссылка задач, текстовые статусы и defaults. Kanban/формулы этой библиотеки пока целевые, а не готовые возможности.

**Markdown:** отдельный текстовый тип, обычный ввод с необязательным предпросмотром; чтение заголовков, выделения, списков, задач, таблиц, цитат и кода. HTML показывается буквально и не исполняется. Разрешены только абсолютные http/https/mailto-ссылки; они открываются через ОС. Внешние изображения не загружаются автоматически: показывается ссылка с альтернативным текстом. Поиск и CSV сохраняют текстовую модель. Специальные `[[ссылки]]` пока не реализованы.

**Разделение входящих:** в настройках приёмной коллекции можно выбрать отдельные поля заголовка и тела. Первый ATX-заголовок разбирается, остальной текст сохраняется без обрезки; нераспознанная структура сохраняется целиком. При устаревшем маппинге весь текст подставляется в доступное входящее поле с сообщением. Полный исходный текст защищён от перезаписи при переносе и доступен в карточке в «Исходном содержимом входящих», включая после последующего редактирования. UUID, даты, неизвестные значения и прежние версии сохранены; stale/ошибка записи не оставляют частичного переноса. Схема БД не изменяется, миграции 1–7 сохранены. Android Share ещё не реализован.

CSV: откройте коллекцию → **CSV**, выберите локаль и файл (UTF-8 или Windows-1251), сопоставьте столбцы, проверьте весь файл и первые десять строк, подтвердите импорт. Импорт добавляет новые записи одной транзакцией: ошибка отменяет весь файл, включая версии и журнал. Ограничение входного файла — 100 МБ. Целые числа проверяются без округления; русская локаль принимает `1 234`, `да/нет`, `дд.мм.гггг`; английская — `1,234`, `yes/no`; ISO-даты и `true/false` поддерживаются обеими. Экспорт позволяет выбрать поля и учитывать текущий поиск/фильтры, читает согласованный снимок БД порциями, сохраняет через стандартный desktop-диалог или Android Storage Access Framework. CSV не заменяет архив полной базы и не переносит историю/конфигурации.

До «Сохранить» новой записи в БД нет; «Закрыть» сохраняет только локальный черновик создания. «Отмена» редактирования ничего не пишет. Сеть, аккаунт и почта не нужны. Браузер без нативного адаптера сообщает об этом; подмены SQLite нет. Совместимость с первоначальным примером-прототипом не требуется.

Связи: в настройках поля выберите **«Связь»**, целевую коллекцию этой же библиотеки и одну/несколько целей. Для обратного поля выберите **«Обратная связь»** и исходное прямое поле. В форме — поиск и страницы целей, в карточке — прямые/обратные блоки, переходы с возвратом и **«Создать связанную запись»**. Создание через обратное поле заранее заполняет связь с родителем; «Закрыть» сохраняет только черновик, не создавая запись. Создание через прямое поле атомарно создаёт цель и обновляет источник: ошибка не оставляет сироту. Для одной связи новая цель заменяет предыдущую.

Прямое значение — UUID или `null`, множественное — массив уникальных UUID с сохранением порядка. Самоссылки и циклы допустимы; вычисление формул — отдельная задача. Обратные значения вычисляются и не записываются в `records`, версии или журнал. Удаление/отсутствие цели сохраняет ссылку; неизменённая недоступная ссылка не мешает редактировать остальные поля. Новую недоступную цель выбрать/импортировать нельзя. Межбиблиотечные связи отклоняются ядром. Цель и кратность существующего поля не меняются без проверенного преобразования — создайте другое поле.

В списке показаны до трёх актуальных подписей связи с числом остальных; полная выборка в карточке виртуализируется и читается страницами по 50. Фильтры связей — содержит UUID / не содержит / пусто / заполнено; сортировка и группировка на этом этапе доступны для простых типов. CSV хранит прямые UUID (множественные — JSON-массивом), обратные экспортирует вычисленным массивом и пропускает при импорте. CSV коллекции не является переносом связанного графа в другую базу: цели должны уже существовать с теми же UUID.

«Входящие» доступны без библиотеки: глобальное **«+ Во входящие»** открывает форму текста/ссылки. До «Сохранить» запись не создаётся. В карточке **«Перенести в коллекцию»** предлагает библиотеку и коллекцию, подставляет содержимое в назначенное входящее текстовое поле и проверяет обязательные поля/defaults. «Отмена» сохраняет источник без изменений. Успешный перенос атомарно меняет коллекцию и значения той же записи: UUID, все исходные даты и прежние версии сохраняются; HLC, новая версия и журнал отражают перенос. Неизвестные значения не теряются, FTS и связи обновляются в той же транзакции. Устаревшая форма не перезаписывает изменённый источник. Системная структура не редактируется и не появляется среди пользовательских библиотек. Файлы и Android Share — последующие этапы.

Системные контейнеры включены в актуальный bootstrap. Android acceptance проверяет перенос через настоящий community SQLite bridge; статус выполнения — в CI конкретного коммита.

**Быстрые формы:** в коллекции откройте «Быстрая форма» и выберите подмножество полей; «+ Быстрая запись» открывает его для создания записи. Правила, обязательность, подсказки и defaults наследуются из обычной формы. Остальные поля заполняются defaults, включая `0`/`false`. Скрыть обязательное поле без допустимого default нельзя. Изменение обычной формы/полей перепроверяется при каждом быстром сохранении; несовместимая конфигурация не создаёт частичную запись. «Закрыть» сохраняет черновик; явное сохранение создаёт одну обычную версию и удаляет его. Форма, карточка, список и быстрая форма сохраняются независимо. `quick_forms` включены в актуальную схему как самостоятельные UUID/HLC UI-конфигурации с журналом при active/paused. Быстрые одношаговые действия без пользовательской версии — отдельная последующая задача.

## Windows x64

Установить Git, **Node.js 24 LTS**, Rust stable (MSVC), Visual Studio Build Tools с workload **Desktop development with C++** и Windows SDK, Microsoft Edge WebView2 Runtime. Tauri 2: [официальные prerequisites](https://v2.tauri.app/start/prerequisites/). SQLite собирается из исходников через rusqlite bundled; отдельно устанавливать SQLite не нужно.

PowerShell:

```powershell
git clone https://github.com/Hemlig371/tessera.git
cd tessera
npm ci
npm run dev:desktop
```

Команда запускает Vite и Tauri с настоящим Rust SQLite. Dev-профиль изолирован: `%APPDATA%\app.tessera.personal.dev\databases\app.sqlite`; обычная сборка — `%APPDATA%\app.tessera.personal\databases\app.sqlite`. Не копируйте активный `.sqlite` отдельно от WAL. До первого публичного релиза актуальная dev-схема создаётся единым bootstrap без обязательных переходов между dev-версиями; несовместимую dev-базу нельзя молча удалять или перезаписывать — сначала предложить экспорт. После первого релиза обновления выполняются последовательными версионированными миграциями с согласованной резервной копией перед рискованными изменениями.

```powershell

npm run lint

npm run test:native
npm run test:native-api
```

После изменения Rust-зависимостей проверить оба Cargo.lock. `cargo test --locked --manifest-path src-tauri/Cargo.toml` требует системные зависимости Tauri; `test:native` проверяет SQLite-адаптер без WebView.

## Структура

| Файлы | Ответственность |
| --- | --- |
| `src/core/ports.ts`, `model.ts`, `hlc.ts` | границы адаптеров, типы, HLC |
| `src/core/schema.ts`, `migrate.ts`, `sqlite-check.ts` | актуальный DDL/bootstrap до первого релиза; после релиза — последовательные транзакционные миграции с checksum/backup и приёмка SQLite |
| `src/core/history.ts`, `change-journal.ts` | Top-20, маркеры очистки/отсечения, жизненный цикл и подтверждённая компактация транспортного журнала |
| `src/core/repository.ts`, `relations.ts`, `quick-forms.ts` | UUID, библиотеки/коллекции/поля/records JSON, профили, атомарные версии/журнал/FTS |
| `src/platform/` | последовательное соединение, Tauri/community SQLite; без browser fallback |
| `src/ui/`, `src/locales/` | React, Zustand для навигации/форм, TanStack Virtual, i18next ru/en |
| `src-tauri/sqlite-bridge/`, `src-tauri/src/` | узкий Rust-адаптер и Tauri-команды; single-instance writer |
| `android/` | Capacitor-проект, запрет backup ОС, инструментальные тесты |
| `tests/`, `scripts/`, `.github/workflows/ci.yml` | dev/CI-проверки и сборки |
| `AGENTS.md` | постоянные правила проекта |

Единый транзакционный bootstrap создаёт текущие таблицы и индексы без промежуточных ALTER/конверсий. `schema_id`, checksum DDL и версия формата проверяются до повторного запуска. Неизвестная, изменённая или промежуточная dev-схема отклоняется с сохранением базы. Неудача DDL откатывает всю инициализацию; повторная попытка создаёт чистую схему. Пустая база не требует резервного snapshot.

`SerialDatabase.close()` сразу запрещает новые задачи, завершает принятую очередь и возвращает всем ожидающим один результат закрытия. `checkDatabaseIntegrity()` выполняет quick/integrity и проверку внешних ключей для диагностики/будущего импорта; общий native acceptance использует полную проверку. Обычный запуск сохраняет дешёвую проверку SQLite.

Индексы JSON создаются по флагу **«Индексировать»** и постоянным требованиям списка, удаляются при исчезновении обоих оснований. Текстовая сортировка использует локальные нормализованные ключи русского алфавита (`е`, затем `ё`), одинаковые на всех платформах; это не полный ICU Collator для всех языков. FTS/ключи/`search_documents` и `relation_index` — производные локальные данные: не попадают в пользовательские версии или журнал, перестраиваются возобновляемыми транзакциями по 200 записей. На desktop длительные SQL-команды исполняются вне UI-потока. Неизвестные UUID значений сохраняются. Конфигурации UI — самостоятельные объекты с UUID/HLC/device/deleted_at и атомарным журналом.

## CI и состояние этапа

Workflow: **любой push (включая tags), pull_request и вручную**. Сначала Ubuntu/Windows checks и HLC property tests, затем Windows x64 NSIS, macOS ARM64 DMG, Linux x64 AppImage, Android debug APK и API 35 x86_64 emulator. Артефакты загружаются после успешных проверок. Tags пока дают Actions-артефакты без публичного релиза. Сборки не подписаны релизными сертификатами; секретов в репозитории нет.

В CI предусмотрены Windows `tauri dev` smoke (WebView должен исполнить TS-bootstrap в нативной БД), Linux Tauri/WebKit WebDriver E2E с перезапуском процесса и Android WebView/Capacitor-контракт с повторным открытием БД. Merged manifest проверяется отдельно. Acceptance JS собирается только отдельной test-конфигурацией/application ID; обычные APK/desktop этих тестов не содержат.

**Проверки этапа 3:** локально выполняются typecheck, lint, unit, DB/API, HLC, Rust, Playwright и production build. Измерения 50K сохраняются в `work/scale-*.json` и CI-артефактах `scale-metrics-*`; они привязаны к машине/адаптеру, без обещания скорости на любом устройстве. Набор содержит 50 000 записей, 21 поле, 4 999 связей и проверяет обратную выборку; формирование индекса и связанное создание проверяются на реальной SQLite. Android измеряется в отдельном emulator job и выводит `STAGE3_SCALE` в instrumentation report.

**Подтверждённая исходная нативная матрица:** `3e4a7bb` (0.14.0), [8/8 jobs](https://github.com/Hemlig371/tessera/actions/runs/43762924771), включая отдельные экраны, Android Emulator и Linux WebView. Она не подтверждает последующие изменения bootstrap/истории/журнала; их статус проверяется отдельно.

**Статус конкретного коммита:** [GitHub Actions](https://github.com/Hemlig371/tessera/actions). Зелёный предыдущий прогон не подтверждает новый код. Сборка APK сама по себе не доказывает выполнение SQLite bridge. При падении JUnit-assert выводится в GitHub Checks, полный отчёт сохраняется артефактом.

**Ручная приёмка:** физический Android/OEM lifecycle, системный выбор CSV на конкретных устройствах, установка и поведение подписанных Windows/macOS сборок. В локальном Cloud нет KVM и GTK/WebKit headers; GUI/emulator-проверки выполняются в CI. APK — debug, desktop-пакеты без релизной подписи. На Android отмена/ошибка экспорта пытается удалить незавершённый SAF-документ; успешное удаление зависит от document provider. Desktop пишет временный файл рядом с целевым и заменяет его после завершения.

**Далее по §16:** Android Share, вложения, Decimal/формулы, полный каталог типов, Top-20/корзина, архив базы, сводки, адаптивный UX и почтовая синхронизация. Черновики создания, профили текущих режимов, пресеты и Markdown уже реализованы. HLC-тесты не означают готовый sync-протокол.
