# Tessera — текущий статус и продолжение

Срез передачи 18.11.2026: **0.20.0**, Android code **21**, схема `tessera-dev-bootstrap-2`. **M1 и M2 закрыты по обязательной автоматике с указанными test-only UI пробелами; M3 — сохранённый неинтегрированный WIP, не принят.** Физический телефон остаётся ручной проверкой. Доказательства разделены по SHA; одного полного зелёного HEAD нет. Текущий HEAD/дерево проверять Git.

Директива пользователя 17.11: приоритет функционала и корректности логики; только необходимый UI, минимум UI-тестов, полировка и широкая UI-приёмка в конце. Платформы: Android → Windows → macOS; Linux можно опускать при задержках. Третий полный прогон M2 не запускать.

- **Есть:** SQLite/общий TS Core, CRUD/CSV/поиск/связи, каталоги и старты библиотек, UI форм/карточек/профилей/пресетов, черновики создания, история Top-20, общая корзина/tombstones, локальные файлы/хеши/GC.
- **Частично §4.1:** навигация/старты/ярлыки есть; Android-блокировки/системной авторизации/recent-apps нет. Desktop-блокировка исключена пользователем.
- **M2 / §5 реализован, обязательная автоприёмка завершена:** типы/Decimal/деньги/Secret, формулы и агрегаты, быстрые действия с UI. Результаты локальных и native-проверок и границы UI-доказательств ниже.
- **Нет §8.5:** экран крупных вложений, групповой экспорт в папку/открытие папки. Заготовка API не является готовым экраном.
- **Частично §9:** Back/темы/ярлыки/URL есть; прямой Android Share, календарь/напоминание Intent и desktop .ics отсутствуют.
- **Есть §10:** ZIP/manifest/NDJSON, staging/проверка/rollback, стартовый выбор и новый device_id. Windows fsync и Android-компиляция исправлены; границы native UI карантина и ручных проверок ниже.
- **Частично §12:** bootstrap/SQLite integrity/приватные файлы/GC/аварийные тесты/allowBackup=false есть; диагностики с экспортом без секретов нет.
- **Частично §14.3:** CRUD/CSV/история/корзина/SQLite/черновики/файлы/50k покрыты; архивная native-приёмка, Decimal/формулы, полный sync/crypto/Share и сквозная матрица открыты.
- **M1 закрыт по обязательной автоматике:** Windows/Linux native, три desktop-сборки, настоящий Tauri blob-preview, Android archive-flow, APK и force-stop/recovery. Один test-only native picker в карантине; физический телефон/SAF остаются ручной приёмкой.
- **M2:** каталог типов по пользе (Decimal/деньги, стабильные варианты выбора, время/дата-время/диапазон/длительность, URL/email/телефон/штрихкод, формула/агрегат/секрет, остальные); счётчик/рейтинг/прогресс/слайдер. Точная арифметика до 5 знаков half-up/индексный ключ; безопасный парсер без eval, циклы/ошибки/инвалидация/агрегаты прямых и обратных связей, сортировка/фильтры/группировка по кэшу; быстрые действия без версии.
- **M3:** Kanban/календарь/дерево, сводки библиотеки, Сегодня/Неделя, итоги всего запроса; недоступные режимы не выдавать за готовые. Гант/граф вне v4.0.
- **M4:** недостающие Share/внешние действия/Android-блокировка/диагностика/крупные вложения/миниатюры по сверке выше.
- **M5:** файловый протокол независимых SQLite, baseline из архива, типизированные события/курсоры/ACK/идемпотентность/LWW/Top-20/clear markers/tombstones/pause-resume-detach/recovery; зашифрованные chunks ≤порога, крупные метаданные/подсказки; test:sync и sync-chaos.
- **M6 после M5:** WebCrypto AES-256-GCM/QR/secure storage/устройства/SMTP-IMAP/лимиты провайдера/долгий offline. Почту не удалять; реальный ящик вручную проверяет пользователь.
- **M7:** сквозная §14.3, ≥50k/20–30 полей/тысячи связей, безопасность/адаптивность и ручные §14.4; весь карантин разрешить с пользователем.

## M1: что уже написано

- WAL-согласованная транзакция → открытый ZIP STORE/ZIP64, manifest/model v1, доменные NDJSON без DDL/производных/локальных очередей/ключей/паролей/ID установки, SHA-256/CRC. Малые оригиналы включены, крупные/отсутствующие — заглушки; текущие записи/история/clear markers/tombstones сохранены.
- Импорт в отдельную текущую SQLite/файлы с проверкой формата/хешей/связей/целостности/места. Новый device_id; dataset сохраняется либо новый по выбору; sync выключен, архивная точка не подменяет подтверждённые курсоры.
- Старт «Создать / Импортировать», общий экран, предупреждение об открытом ZIP/исключённых черновиках, предложение экспортировать текущую базу и явное подтверждение замены. Приватный журнал с SHA-256 откатывает/завершает смену DB/байтов/локальных очередей/черновиков; Tauri повторно открывает соединение после renderer reload, Android использует прежний bundled SQLite.
- Привязка/повторная привязка только через file/image, произвольный UUID в тексте не ссылка; старые файловые определения после переноса/удаления сохраняют доступ. CSP production/dev разрешает blob:; настоящий Tauri preview принят отдельными native-прогонами ниже.
- UI-переполнение при 320 px/150% исправлено переносом инструментов; каталог ждёт применённый масштаб и использует точную роль textbox/уникальную фикстуру.

### Известные проблемы / ручные проверки

- **M2 Android lifecycle исправлен, не карантин:** `a242304` выявил orphan SQLite write lock после Activity recreation. На `e85a97b` pinned SQLite 8.1.1 cleanup с checksum/idempotency guard закрывает соединения и откатывает незавершённую транзакцию на owner thread. [Android-only 44148895679](https://github.com/Hemlig371/tessera/actions/runs/44148895679): 10 instrumentation data/recreation тестов и 8 отдельных force-stop/relaunch фаз прошли, production APK собран. Windows native (9 Rust + 329 Node/Rust DB/native) и Windows/macOS desktop подтверждены [44140734992](https://github.com/Hemlig371/tessera/actions/runs/44140734992) на `a242304`; guards проверяют допустимые Android-only отличия. Linux application и широкие UI пропущены по директиве пользователя; пропуски не выдаются за проверки текущего SHA.
- **Постоянная dev-подпись:** пользователь разрешил смену ключа. Прежние M1/M2 CI APK имели разные случайные debug-сертификаты; обновление поверх несовместимо. Actions secrets недоступны текущей интеграции (HTTP 403), поэтому для debug закреплён публичный тестовый `android/app/tessera-debug.keystore`; release его не использует. SHA-256 сертификата `ae62fc4e828d4ac9d33bb38117d73cf55df33cab23ecd08e322af1ff6959ee40`; фактический APK проверяется. Первый переход: экспорт БД во внешнюю папку и проверка ZIP → переустановка → импорт. Следующие debug APK обновляются одной подписью.

- **Windows fsync исправлен и проверен:** write handle без create/truncate, Linux-путь прежний. На `e3bb175` Windows прошёл все replacement/crash и DB/native-контракты.
- Android nullable `JSObject.getString()` и отсутствующий публичный `OsConstants.O_DIRECTORY` исправлены явной проверкой строк и read-only directory fd + fsync; APK/emulator прошли на `bbcd7a0`.
- **Карантин `M1-native-archive-picker`**, фрагмент `scripts/desktop-e2e.mjs`: read-only `__TAURI_INTERNALS__.invoke` (locked Tauri 2.12.5) не подменяет save picker; timeout «Экспорт · 0». Две локальные GTK-попытки исправления управления диалогом: (1) клавиши в toplevel не установили фокус; (2) явный focus выбрал путь с двойным `.zip`. По политике пользователя фрагмент исключён из обязательного прогона до конца M1; native UI export/replace этим прогоном не подтверждён. Остальной WebView-сценарий, blob-preview, native DB/replacement/crash и Android archive-flow остаются обязательными. Перед M7 исправить либо удалить с ведома пользователя.
- **M2 UI-черновик не допущен / test-only карантин `M2-typed-formulas`:** новый сценарий после двух неудачных правок (неоднозначный выбор формульного результата → ID поля; стартовый 5-секундный timeout → ожидание готовности 15 с) упал на `check()`: проверил прежний checkbox во время async-сохранения/замены DOM, итоговая запись и UI уже `true`. Обязательный CI его не включает; нестабильный новый тест не коммитится по AGENTS.md. Черновик/trace/context сохранены в `work/m2-ui-quarantine/`; до конца M2 не отлаживать, перед M7 исправить и проверить при итоговой UI-приёмке. Это пробел UI-доказательств M2, не карантин данных.
- Прежний Windows presets pending-COMMIT таймаут закрыт увеличением ожидания до 15 с и успешным сценарием в обоих M1 CI; не отлаживать заново без нового дефекта.
- Android DocumentsProvider не гарантирует атомарность внешнего файла при force-stop финального копирования. Успех только после записи/закрытия; неполный ZIP при импорте отклоняется, исходная база экспортом не меняется.
- Физический телефон/OEM, реальные SAF-провайдеры, launcher pin, календарные приложения/почта/подписи — ручная приёмка по §14.4. Шаги M1 на тестовой БД: запись с изображением → офлайн «Экспорт БД» → открыть ZIP/manifest → изменить запись → выбрать ZIP, проверить и подтвердить замену → проверить запись/изображение и перезапуск. Повторить импорт на чистой установке и отклонение повреждённого ZIP без изменения БД.
