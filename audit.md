## Завершённый участок M3 — фильтр дат (21.11)

- `ListOptions.date_selection`: null снимает условие, today/week сохраняются относительно локальной даты устройства, range — включительные границы. Profile validation/Repository/SQL применяют условие до LIMIT; date/local_datetime/пересекающийся date_range и статическая вычисляемая дата поддержаны, динамический NOW запрещён для фильтра/индекса.
- Query cursor содержит разрешённый интервал: вчерашний Today cursor отклоняется, Week остаётся действительным в пределах недели. `freezeQueryDates()` фиксирует в памяти один интервал для многостраничных totals/projections/formulas/widgets; на диск абсолютный Today не записывать. Собственная сводка без профиля явно снимает default date condition.
- UI: Конструктор → Список активного представления → Фильтр по дате (поле/Сегодня/Текущая неделя/диапазон) → Сохранить настройку. Настройка независима по профилям; над списком видны активный период и его фактические включительные даты (для Today — один день, для Week — понедельник–воскресенье). Используется общий freezeDateSelection, вычисленные границы не сохраняются. Дополнение с границами проверено typecheck/lint и 8 адресными unit/Node DB тестами; UI/native повторно не запускались. Обновление списка по локальной полуночи/focus/возврату приложения; пустой результат объясняется фильтром. Переключение профилей записи не меняет.
- Локально typecheck/lint, 207 unit/Node/Rust DB тестов в 28 файлах прошли (включая архивный roundtrip относительного профиля). Логи адресно: `work/m3-dates-typecheck.log`, `work/m3-dates-lint.log`, `work/m3-dates-final-tests.log`. Версия остаётся 0.20.0/code21 до завершения значимого M3; APK M2 выше не содержит этот новый UI. Новый UI-сценарий не прошёл навигацию и отмечен fixme по правилу двух правок (см. карантин); успешную E2E-проверку фильтра не заявлять. Full CI/native/телефон на этом участке не запускались.
- Для ручной проверки на будущей сборке: две записи на разные даты → два профиля «Сегодня»/«История» → настроить условие в первом → переключить профили → задать диапазон с обеими включительными границами → сохранить/перезапустить; состав и история записей остаются прежними. Полуночные границы/курсор проверены DB-тестом; системные lifecycle/OEM здесь не заявлены.
