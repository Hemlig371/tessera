# Tessera v4.0 — реализация и подтверждённые проверки

### Очередной интеграционный checkpoint

- Устранено расхождение ключей `collectionCount_*` в русской и английской локализациях, которое обнаружил GitHub Actions unit-test `model.test.ts`.
- Кнопка создания записи получила явное доступное имя: скрытая подпись на компактном телефоне больше не меняет семантику действия.
- Добавлены тестовые визуальные контрольные скриншоты `tests/e2e/tessera-v4-visual.spec.ts` (390 px, 1280 px и компактный 320 px) через GitHub Actions; тесты не заменяют ручное сравнение с тремя утверждёнными изображениями.
- Компактные карточки вложений получили явное меню для редких файловых операций; технические действия по-прежнему доступны по запросу.

## Стандартный интеграционный прогон v4

На текущей серии коммитов новые отдельные `ConstructorOverview` и `TopbarOverflow` заменяют первоначальные перегруженные маршруты, не изменяя слой данных. Для основных Playwright-проверок обновлены переходы через пользовательское мобильное меню; сценарии сохранения и восстановления остаются. Эта контрольная точка запрашивает полный нативный CI и оба изолированных QA-инсталлятора. Результаты и недочёты необходимо фиксировать по фактическим job statuses и логам, а не по промежуточному отчёту.

## Контрольная точка перед финальной проверкой (без локальных тестов)

- Новый отдельный экран конструктора использует `ConstructorOverview` и уже существующие редакторы схемы, макетов и профилей; библиотечные/коллекционные каталоги доступны из самого конструктора. Структура не изменяется при просмотре реальных данных.
- Повседневные списки и подробная запись используют `tessera-v4.css`, карточки с изображениями и компактные значения поддерживаемых типов. Обложка отображается только при наличии реального изображения в поле записи. Редактирование значений остаётся отдельной формой.
- Android: `SystemBars.insetsHandling='css'` Capacitor 8 с `--safe-area-inset-*`, резервный `env()`, тема системных значков, visualViewport при IME. Не добавлялся второй нативный обработчик insets; физическая проверка Galaxy Z Fold7 остаётся частью ручной приёмки.
- Обязательные критерии перед передачей в ручную приёмку: зелёный полный GitHub Actions для **одного** SHA, обычные APK и Windows NSIS на том же SHA, изолированные QA-пакеты, подтверждение отсутствия тестовых данных в production bundle и просмотр доступных скриншотов. Релизы/теги не создавать.
- Первоначальный CI `7d6b1cf` и последующий `9f2b27f` упали в старом Playwright-пути навигации; выявленные причины — скрытая запись после выхода из конструктора и недоступная мобильная кнопка настроек. Соответствующие исправления в следующих коммитах. Ни один прежний успешный статус `Report main CI result` не является свидетельством полного зелёного matrix workflow.

## Новый визуальный контракт — работа в main (22 ноября 2026)

- Исходный HEAD до переработки: `ca75dfed1ab5b6cd29a74bae4db1a6e0cd5682b5`; исходные структура и UX-спецификация изучены.
- Три утверждённых макета заменяют Hybrid UI как визуальный эталон: каталог библиотек, список/подробная запись рецептов, задача с секциями и вложениями. UX-контракт обновлён в `ui-specification.md`. Это **ещё не результат ручной визуальной приёмки**.
- Начат инкрементальный переход: `src/ui/tessera-v4.css` (семантические токены, Android safe-area/IME и адаптивность), `Catalog.tsx` (горизонтальные компактные карточки и достоверная вторичная информация), `App.tsx` (главная мобильная навигация, «Недавние», действия записи, миниатюры из существующих полей изображений, отдельная рабочая область конструктора), `RecordCover.tsx` (обложка записи из прикреплённого изображения), `Icon.tsx` (локальные символы), `main.tsx` (реакция на visualViewport). Старый слой стилей временно остаётся ради функциональности существующих экранов.
- Repository API, SQLite, модели, миграции, sync, mail, экспорт/импорт и операционные адаптеры **не менялись**. Миниатюры используют существующий API чтения изображений; библиотечные метаданные — `listCollections`.
- Первый полный Actions run для `c2b3ed0` обнаружил предупреждение ESLint о зависимости `t` в `App.tsx`, из-за `--max-warnings 0` задания checks упали. Исправлено следующим коммитом. Последующие проверки и QA сборки **должны оцениваться по фактическому run текущего HEAD**; статусные отчёты и отменённые запуски не считать успешным CI.
- Не запускались локальные тесты. QA-workflow коммита `ce09b6b` успешно собрал изолированные установщики, но этот успех **не относится автоматически** к более позднему HEAD. Физические Samsung Galaxy Z Fold7, другие телефоны/планшеты и установленный Windows WebView2 ещё не проходили ручную приёмку. Дизайн-переход частичный: требуется дальнейшая визуальная доводка, полная проверка конструктора и Android системных областей, полный CI и оба типа инсталляторов именно на финальном HEAD.



**Состояние:** предрелизная реализация, автоматическая приёмка завершена; публикация и ручная приёмка реальных устройств/провайдеров не выполнялись. Версия исходников — `0.24.0`, Android `versionCode 25`. Целевое имя продукта — **Tessera v4.0**; текущая версия в package/build-конфигурациях не является опубликованным релизом.

**Контракты:** [функциональные требования](target-specification-v4.0.md) и [интерфейс](ui-specification.md). Этот документ описывает только фактическую реализацию, доказательства и ограничения, не заменяет требования. Правила сопровождения — [AGENTS.md](AGENTS.md), команды — [README.md](README.md).

## Hybrid UI: реализация после этапа 2 (22 ноября 2026)

Следующие пользовательские маршруты добавлены поверх общего React UI и существующего Repository API, **без изменения SQL-схемы**:
- Самостоятельный раздел глобальных настроек из верхней панели (`src/ui/App.tsx`), доступный без библиотеки и конструктора. Оформление оставлено также прямым действием. SMTP/IMAP открывается на поддерживаемых нативных платформах через существующий защищённый транспорт, без новых утверждений о поддержке конкретных внешних провайдеров.
- Конструктор строк поддерживает перенос строк и полей, видимую цель сброса, прежние кнопки вверх/вниз и выбор поля через select. Структурный предпросмотр обновляется до сохранения, без записи в БД.
- Несколько именованных макетов подробной карточки в совместимом JSON `ui_configs(kind='card')`, привязка `detail_layout_id` в существующей конфигурации профиля. Макеты читают одну запись; отсутствующий/удалённый ID использует стандартную карточку. Прежняя кнопка «Карточка» и формат `fields/rows` сохранены; отдельный «Макеты записи» предназначен для управления альтернативами.
- Новые unit / browser E2E сценарии добавлены только в dev/CI. Обычная установка не получает фикстур.

**Пределы доказательств:** это расширение не закрывает весь `ui-specification.md`: требуются ручная визуальная проверка на Android и Windows, контраст/150%-масштаб, полный UX-проход редактора свойств/drag на touch, workflow синхронизации с реальным SMTP/IMAP и оставшиеся подробные сценарии. Только успешное прохождение **нового** полного GitHub Actions run может подтвердить соответствующий набор автоматических проверок; зелёный отчёт status-workflow или пропущенный QA-job сами по себе недостаточны. Локальные тесты не запускались.

## Hybrid UI v4: структурная переработка рабочего пространства (22 ноября 2026)

Задача отделена от прежней CSS-полировки: существующее ядро/Repository/SQLite и протокол синхронизации сохранены, но интерфейс допускает новую структуру и не обязан воспроизводить старый UX. На текущем HEAD реализованы:
- Новая оболочка `hybrid-shell` с контекстной навигацией и оформлением рабочего пространства, каталогов, записей и редакторов (в том числе адаптация Android и desktop).
- Отдельный `Hybrid`-конструктор: каталог полей, центральное живое представление безопасных демонстрационных значений, панель свойств, перестановка полей/строк mouse/touch, предпросмотр телефона/планшета/desktop, тёмного вида, Undo/Redo, сброс шаблона и подтверждение отмены несохранённых изменений. JSON UI-конфигураций сохраняется через прежний Repository только по Save.
- Группированные глобальные настройки: синхронизация и почта, оформление/язык, архив и обслуживание. Переход к дочерним настройкам возвращает в корневые настройки.
- Отдельная полноширинная форма создания/изменения записи, новая система поверхностей/отступов и sticky save/cancel.
- Существующие виды коллекций, черновики, именованные макеты, все операции Repo/синхронизации сохранены. Новые browser tests проверяют canvas, Undo/Redo и отсутствие записи при отмене; старые UI-тесты изменены под выбранное поле и расположение языка в настройках.

**Пределы**: это новый интерфейс и значительная визуальная реконструкция, но не доказательство полной приёмки всех пунктов `ui-specification.md`. Требуются ручные скриншоты и проверки на реальных устройствах; предпросмотр пока использует безопасные демонстрационные значения, отсутствует визуальная палитра всех типов декоративных блоков и нет полного измеренного визуального регрессионного отчёта. Полный GitHub Actions checkpoint и изолированные QA-пакеты запрошены маркерами коммита; не считать их успешными до завершения соответствующих jobs. Локальные тесты не выполнялись.

### Hybrid UI — исправления после полной приёмки и новый checkpoint (22 ноября 2026)

Полный browser run `45054425725` показал 8 ошибок на Ubuntu (33 E2E-сценария прошли): старые проверки искали архив/корзину и язык в скрытых мобильных кнопках, параметры профиля были перенесены в раскрываемые настройки, редактор быстрой формы требовал выбора поля, а новая компоновка формы не складывала три колонки при ширине 1060 px. В конструктор также добавлен **опциональный предпросмотр из реальной записи, только чтение**, с сокрытием секретных значений и безопасным fallback на демонстрационные данные. Пользовательские записи и история при просмотре не изменяются.

Для текущего HEAD запрошены отдельные **полные** `[m7 ci] [full ci]` GitHub Actions и **изолированные** `[qa ci]` сборки Android/Windows. Пока эти run не получили status `completed/success`, соответствующую приёмку нельзя считать завершённой. Локальные тесты запрещены и не запускались; обычные установщики не содержат QA-фикстур.

### Hybrid UI — проверка маршрутов после полного CI

E2E-контракты обновлены с учётом намеренно новой навигации: список — через «Настройки списка», архив и корзина — через глобальные настройки, свойства конкретного поля — через выбранный блок; при выходе из корзины используются два уровня возврата. Android/desktop формы должны сворачивать колонки при рабочей ширине менее 1100 px. Переключение локализации проверяется через глобальные настройки, включая цикл RU/EN. Редактор отображает данные реальной записи **только в памяти для предпросмотра**, без сохранения и с маскированием секретов.

Запрошена финальная единая проверка `[m7 ci] [full ci]` и отдельные `[qa ci]` пакеты. Зелёный итог признаётся только после `completed/success` у основного workflow и QA-workflow на одном SHA. Данные, Repository, протокол почтовой синхронизации и schema не менялись.

## Реализованная система

- **Local-first:** Android (Capacitor/Kotlin), Windows/macOS и опционально Linux (Tauri/Rust), общие React/TypeScript/Vite, Zustand для UI, i18next, TanStack Virtual. Обязательного сервера, аккаунта или сети нет. Production браузерного SQLite/localStorage-fallback нет.
- **Данные:** `src/core/repository.ts` — единый публичный API и путь записи. Бизнес-правила, DDL/bootstrap, типы, формулы, HLC/LWW, история, журнал изменений и синхронизация — в общем TS-ядре. `src/platform/serial-database.ts` сериализует операции; Kotlin/Rust предоставляют платформенные SQLite/OS-адаптеры. UI не исполняет SQL. Текущая схема — `tessera-dev-bootstrap-2`, **без миграций между промежуточными dev-схемами**. Несовместимую БД нельзя молча сбрасывать.
- **Пользовательские возможности:** библиотеки, коллекции, типизированные поля и JSON-значения, связи, Markdown/«Входящие», формы и пресеты создания, локальные черновики только новых записей, профили отображения, фильтры, Kanban/календарь/дерево/сводки, Decimal и формулы, поиск/FTS, виртуализированные списки, история Top-20, корзина, быстрые действия, вложения, CSV, архивный экспорт/импорт с проверкой и восстановлением. Функции не требуют предметно-специфических таблиц.
- **Синхронизация только по согласию:** независимые SQLite, локальный протокол change journal/replay/ACK, baseline, LWW, tombstones, история, pause/resume/detach, защита от повторов и сбоев; AES-256-GCM для конвертов, квитанций и частей вложений. QR используется для сопряжения; Android — нативные SMTP/IMAP, Android Keystore и камера; desktop — системный TLS SMTP/IMAP и OS-хранилище секретов (Windows Credential Manager / macOS Keychain). Сообщение «отправлено» не означает «применено». Пароли/ключи не сохраняются в обычный архив.
- **Хранилище и перенос:** архив базы — **незашифрованный ZIP** с manifest/JSON/NDJSON и малыми оригиналами/хешами, для больших файлов — предусмотренные метаданные/заглушки; пользователь должен учитывать конфиденциальность. Нельзя копировать активный `.sqlite` без WAL-контекста. Android Storage Access Framework не гарантирует атомарность финальной записи внешнего ZIP: успех показывается после закрытия файла, неполный архив при импорте отвергается. Внешняя копия/восстановление — пользовательская операция; runtime recovery не заменяет backup.

## Эксплуатационные условия

- Для разработки — Node.js **24.x**, Rust stable и нативные зависимости Tauri; для Android — JDK **21**, Android SDK/API **36** и Gradle wrapper. Сборки и команды подробно описаны в [README.md](README.md); фактические шаги CI — в [`.github/workflows/ci.yml`](.github/workflows/ci.yml).
- Windows dev-профиль `%APPDATA%\app.tessera.personal.dev` отделён от `%APPDATA%\app.tessera.personal`. Нельзя считать dev-схему совместимой с произвольной будущей/старой базой и нельзя делать автоматический destructive downgrade. Изменения после публичного релиза требуют версионированных миграций.
- Пакет `@capacitor-community/sqlite` закреплён на **8.1.1**; `npm ci` применяет checksum-проверенный идемпотентный lifecycle-патч через `scripts/patch-sqlite-lifecycle.mjs` для rollback/close на owner thread при WebView recreation. Обновление зависимости требует отдельной проверки этого контракта.
- `android/app/tessera-debug.keystore` — постоянный **публичный тестовый** сертификат (alias `androiddebugkey`, пароль `android`), **не релизная подпись**. Перед заменой APK с иной подписью следует сохранить внешний ZIP-архив, проверить его и только затем переустанавливать и импортировать. Не удалять данные пользователя ради обновления.
- Секретные поля маскируются, исключены из общего FTS/сводок/диагностики, но маскирование и Android UI-lock **не шифруют SQLite или экспортный ZIP**. Android lock опирается на системную авторизацию, собственного PIN нет. Реальные почтовые секреты — только в защищённых OS-хранилищах.
- Linux application/GTK native E2E не входит в принятую приоритетную матрицу. Наличие Linux путей в проекте не означает их полного подтверждения итоговым run.

## Ограничения и ручная приёмка перед публикацией

**Открытый test-only quarantine:** `scripts/desktop-e2e.mjs` исключает сценарий нативного GTK/Tauri save-picker для UI экспорта/замены архива. Покрытие Core archive/SQLite, Android replacement и native file/recovery не заменяет этот UI-путь. Сценарий требует ручной проверки или отдельного исправления и повторной проверки, а не удаления работающих data-тестов.

**Не подтверждено автоматической матрицей:** полноценный визуальный проход на физических Android WebView / Windows WebView2 / macOS WKWebView, все контрастные состояния, OEM энергосбережение и background/recreation, реальные SAF-провайдеры и Share/launcher, камера для QR, системные календарь/напоминания и `.ics` association, реальные IMAP/SMTP аккаунты и особенности OAuth/2FA/TLS/лимитов, долговременное offline-сопряжение, release-подпись Windows/macOS и notarization. Отдельный UI E2E именно для typed-formulas не был добавлен в Git; базовые формулы покрыты unit/DB. Это **пробелы доказательств**, не заявления о найденной ошибке бизнес-логики.

Рекомендуемая **ручная приёмка** — на тестовых данных и с явным разрешением для внешних аккаунтов:

1. Android: установка/обновление, экранные размеры, системная авторизация, WebView recreation, фон/OEM, Share, внешние SAF-папки, системные действия и QR-камера.
2. На отдельной тестовой БД: запись с изображением → внешний ZIP/manifest → изменение → импорт с подтверждением → сверка текста/файла после перезапуска; затем повреждённый ZIP (исходная БД не меняется). Перед сменой сертификата — проверенный внешний backup.
3. Windows/macOS: установка подписываемых впоследствии пакетов, реальные native WebView, файловые диалоги экспорта/замены и системные интеграции. При необходимости отдельно Linux GTK picker.
4. С разрешённым тестовым почтовым ящиком: pairing, TLS/auth, доставка/применение/ACK, повтор, отсутствие сети и возобновление, поведение провайдера; не применять реальные личные данные.
5. Доступность/визуальный осмотр: 390 px с 150% текстом, 1280 px, темы, длинные значения, клавиатура, loading/error, контрастность и навигация на целевых устройствах.

Релиз и release tags отсутствуют. Решение о публикации принимается после отдельной ручной проверки, а не из одного зелёного CI.
