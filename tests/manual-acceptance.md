# Tessera QA — ручная приёмка

Доступны **два отдельных тестовых установщика** из GitHub Actions workflow [Tessera QA packages](https://github.com/Hemlig371/tessera/actions/workflows/qa.yml):

- `Tessera-QA-Android.apk` — Android package `app.tessera.personal.qa`, отдельный от `app.tessera.personal`.
- `Tessera-QA-Windows-Setup.exe` — Windows NSIS с identifier `app.tessera.personal.qa`, отдельным OS user data и именем **Tessera QA**.

**Важно:** оба файла содержат один и тот же сценарный набор, но это **две отдельные локальные базы**. На первом запуске чистой QA-установки база создаётся и наполняется автоматически через Repository API. Повторный запуск **не** перезаписывает данные и не создаёт библиотеки заново. Импорт существующей БД не дополняется фикстурами. Обычные APK/Windows-сборки остаются чистыми: тестовый модуль компилируется только при Vite `--mode qa`.

Все значения демонстрационные; нет реальных паролей, аккаунтов или личной информации. Архив экспорта ZIP **не зашифрован**, даже для тестов.

## Что предустановлено

| Библиотека | Ожидаемые данные | Основной ручной тест |
| --- | --- | --- |
| 01 · Питание | Продукты, завтрак/обед, порции, формулы КБЖУ | Изменить вес 150 → 200 г, убедиться в пересчёте и обновлении агрегатов |
| 02 · Проекты и задачи | 10 задач, 1 вложенная, пресет «Новый баг», Kanban/календарь/дерево | Переместить этап, переключить профили, создать баг и перезапустить |
| 03 · База знаний | 250 материалов, долгий Markdown и взаимные связи | FTS Unicode, пагинация, длинный текст, циклические переходы |
| 04 · Заметки | 6 Markdown-записей и связанная тема | Новая заметка → выйти без Save → восстановить черновик → сохранить |
| 05 · Личные финансы | 8 операций, счет/категория, money, таблица и сумма | На исходных данных **sum = 942.14 ₽**, **count = 8** |
| 06 · Медиаархив | Тестовый PNG 1×1 и текстовый документ | Просмотр, ZIP export/import, восстановление, повреждённый ZIP |
| 07 · Контакты и события | 1 контакт, 3 встречи и календарный профиль | Даты, отношения, системное действие календаря/ICS, fallback |
| 08 · Каталог типов полей | 30 типов: в том числе formula, aggregate, relation, backlink, secret, file/image | Decimal 0.1 → вычисленная формула 0.2; обратный агрегат = 7; секрет скрыт в списке |

## Общие сценарии и фиксация результата

- **Создание и сохранение:** новые поля/коллекции, 0/false/пусто, импорт/экспорт; после закрытия все записанные значения остаются.
- **История и корзина:** два явных Save, восстановление версии, удаление и восстановление записи.
- **UI:** мобильный портрет, 150% размер текста, 1280 px desktop, темы, длинные значения, focus/клавиатура, ошибки и загрузка.
- **Android:** Share, SAF, QR камера, биометрическая блокировка, фон/kill/relaunch и внешние намерения.
- **Windows:** работа установленного WebView2, native file dialogs (особенно архив), CSV, системные приложения.
- **Передача:** экспортировать QA-БД в ZIP, импортировать на другой QA-инстанс **только после отдельного backup** целевой QA-БД; данные не должны смешиваться автоматически. Для sync сначала использовать два независимых набора с подтверждённым baseline и отдельным тестовым ящиком; этот QA installer не включает реальные credentials.
- **Негативный тест:** повреждённый ZIP/некорректная дата/недопустимое значение — понятная ошибка без изменения сохранённой записи.

В журнал ручной приёмки записать платформу, версию APK/EXE, действие, фактический результат, ожидаемый результат и скриншот при расхождении. Из-за отсутствия подтверждённых реальных физических проверок не обозначать такие шаги как «пройдено» до выполнения.

## Как пересобрать QA отдельно

Workflow `qa.yml` запускается ручным dispatch или push-коммитом `[qa ci]` в `main`. Он создаёт два **Actions artifacts**, не GitHub Release. QA Android подписывается **публичным debug** сертификатом; QA Windows setup не имеет релизного code-signing. Эти пакеты исключительно для тестов и не заменяют будущие обычные релизные артефакты.

Для обычной сборки использовать штатные `npm run build:android` / `npm run build:desktop`: они не активируют QA seeding и не используют QA identifiers. Технические детали автоматической матрицы — [implementation.md](../implementation.md).
