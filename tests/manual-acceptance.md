# Tessera QA — ручная приёмка

Доступны **два отдельных тестовых установщика** из GitHub Actions workflow [Tessera QA packages](https://github.com/Hemlig371/tessera/actions/workflows/qa.yml):

- `Tessera-QA-Android.apk` — Android package `app.tessera.personal.qa`, отдельный от `app.tessera.personal`.
- `Tessera-QA-Windows-Setup.exe` — Windows NSIS с identifier `app.tessera.personal.qa`, отдельным OS user data и именем **Tessera QA**.

**Важно:** оба файла содержат один и тот же сценарный набор, но это **две отдельные локальные базы**. На первом запуске чистой QA-установки база создаётся и наполняется автоматически через Repository API. Повторный запуск **не** перезаписывает данные и не создаёт библиотеки заново. Импорт существующей БД не дополняется фикстурами. Обычные APK/Windows-сборки остаются чистыми: тестовый модуль компилируется только при Vite `--mode qa`.

Все значения демонстрационные; нет реальных паролей, аккаунтов или личной информации. Архив экспорта ZIP **не зашифрован**, даже для тестов.

## Визуальная приёмка Tessera v4.0 по утверждённым макетам

**Эталон — три изображения владельца, утверждённые 22 ноября 2026 года**, а не устаревшая Hybrid UI-концепция. Факт зелёного CI не означает, что визуальная приёмка пройдена. Отметки этого раздела заполняет владелец после установки и осмотра на устройстве.

1. **Главная → Библиотеки.** На обычном телефоне — бренд Tessera, число библиотек, белые отдельные горизонтальные карточки с цветной иконкой, названием, достоверной метаинформацией и стрелкой, нижняя навигация «Библиотеки / Недавние / Настройки», контекстный зелёный «+». Нет одновременного дубля списка библиотек в раскрытом sidebar. Проверить пустую библиотеку и длинное имя.
2. **Коллекция → список.** Видны название, компактные поиск и представление, отдельные карточки реальных записей; картинка появляется только для записей с файлом изображения, нет встроенных предметных сущностей «рецепт/задача». Зеленое создание работает одним нажатием, альтернативы доступны отдельной явной кнопкой и меню. Переключение профиля не изменяет данные.
3. **Подробная запись.** Полноэкранный просмотр с отдельным возвратом, опциональной обложкой из пользовательского поля, крупным заголовком, компактными свойствами, группами, Markdown, логическими полями, связями и вложениями. Первичное действие редактирования видно, история/удаление остаются доступными без скрытого удаления жестом. Из одной записи перейти в связанную и вернуться в исходный список.
4. **Редактирование значений.** Отдельная читаемая форма, явное сохранение и отмена; изменение значений не открывает настройку схемы. Проверить обязательность поля, длинный Markdown, файл и незавершённый черновик после перезапуска.
5. **Конструктор.** Отдельная рабочая область выбора библиотеки/коллекции, поля, форма, карточка, список, именованные макеты и представления. Перемещение поля мышью/касанием с видимым предпросмотром и альтернативой с клавиатуры; сохранение конфигурации не перезаписывает пользовательские записи.
6. **Глобальные настройки.** Доступны без включения конструктора: тема, масштаб, вложения, архив, синхронизация и почта (если поддерживаются платформой), диагностика и корзина. Для побочных действий используется компактное меню, не постоянно перегруженная панель.
7. **Android.** Проверить обычный телефон и Samsung Galaxy Z Fold7 в сложенном/разложенном виде, обе ориентации: статусная строка, отверстие камеры, верхняя и нижняя области жестов/трёхкнопочной навигации, выдвижная клавиатура, возврат Android, увеличение текста 150%. Никакой кнопки под системной областью и никакой обрезанной кнопки «Сохранить».
8. **Windows.** При 1280 px и больше — самостоятельная desktop-компоновка с боковой навигацией, ограниченной шириной чтения и форм, видимым фокусом, мышью, клавиатурой и Escape. Не просто растянутый телефон.
9. **Изоляция сборок.** QA Android устанавливается под `app.tessera.personal.qa`, QA Windows — в отдельное пространство; обычные установщики не содержат QA-инициализации, демобиблиотек, тестового SQLite-bridge и тестовых секретов. Проверить, что импорт существующей обычной БД не добавляет фикстуры.
10. **Сравнение с макетами.** Снять скриншоты трёх целевых путей на Android и Windows; сравнить композицию, плотность, размеры текста, цвета, иконки, отступы и пустые состояния. Сборка готова к *ручной* приёмке только после зелёного CI и доступности обычных/QA установщиков одного SHA; само визуальное принятие владелец отмечает отдельно.

## Общие сценарии и фиксация результата

- **Создание и сохранение:** новые поля/коллекции, 0/false/пусто, импорт/экспорт; после закрытия все записанные значения остаются.
- **История и корзина:** два явных Save, восстановление версии, удаление и восстановление записи.
- **UI:** мобильный портрет, 150% размер текста, 1280 px desktop, темы, длинные значения, focus/клавиатура, ошибки и загрузка.
- **Android:** Share, SAF, QR камера, биометрическая блокировка, фон/kill/relaunch и внешние намерения.
- **Windows:** работа установленного WebView2, native file dialogs (особенно архив), CSV, системные приложения.
- **Передача:** экспортировать QA-БД в ZIP, импортировать на другой QA-инстанс **только после отдельного backup** целевой QA-БД; данные не должны смешиваться автоматически. Для sync сначала использовать два независимых набора с подтверждённым baseline и отдельным тестовым ящиком; этот QA installer не включает реальные credentials.
- **Негативный тест:** повреждённый ZIP/некорректная дата/недопустимое значение — понятная ошибка без изменения сохранённой записи.

В журнал ручной приёмки записать платформу, версию APK/EXE, действие, фактический результат, ожидаемый результат и скриншот при расхождении. Из-за отсутствия подтверждённых реальных физических проверок не обозначать такие шаги как «пройдено» до выполнения.

## Как пересобрать QA отдельно

Workflow `qa.yml` запускается ручным dispatch или push-коммитом `[qa ci]` в `main`. Он создаёт два **Actions artifacts**, не GitHub Release. QA Android подписывается **публичным debug** сертификатом; QA Windows setup не имеет релизного code-signing. Эти пакеты исключительно для тестов и не заменяют будущие обычные релизные артефакты.

Для обычной сборки использовать штатные `npm run build:android` / `npm run build:desktop`: они не активируют QA seeding и не используют QA identifiers. Технические детали автоматической матрицы — [implementation.md](../implementation.md).
